# Git 提交信息规范

## 一、提交信息格式

```
<类型>(<范围>): <简短描述>

[可选正文]

[可选脚注]
```

## 二、提交类型（必须）

| 类型 | 说明 | 示例 |
|------|------|------|
| `feat` | 新功能 | feat(账号): 添加游客登录功能 |
| `fix` | 修复 Bug | fix(AI): 修复困难模式响应过慢 |
| `refactor` | 重构（不改变功能） | refactor(数据库): 优化查询逻辑 |
| `style` | 代码格式调整 | style(界面): 调整账号栏样式 |
| `docs` | 文档更新 | docs: 更新 README |
| `test` | 测试相关 | test(账号): 添加登录测试 |
| `chore` | 构建/工具 | chore: 更新依赖版本 |
| `perf` | 性能优化 | perf(AI): 优化 Minimax 算法 |
| `ui` | 界面调整 | ui: 修复按钮对齐 |

## 三、提交范围（必须）

### 前端相关
- `前端`、`客户端`、`界面`、`UI`
- 具体模块：`登录`、`游戏`、`聊天`、`排行榜`

### 后端相关
- `后端`、`服务端`、`服务器`
- 具体模块：`账号`、`AI`、`游戏`、`数据`、`API`

### 示例
```
feat(后端-账号): 添加游客登录功能
feat(前端-界面): 添加账号等级显示
fix(后端-AI): 修复困难模式响应过慢
fix(前端-登录): 修复经验值显示不刷新
```

## 四、规则要求

### 1. 标题行
- **必须** 中文描述，不超过 50 个字符
- 使用祈使语气（"添加"而非"添加了"）
- 不使用句号结尾
- 格式：`类型(后端/前端-模块): 描述`

### 2. 正文格式
正文部分**必须**使用数字序号区分前后端：

```
1. 后端改动：
   - 具体描述...

2. 前端改动：
   - 具体描述...
```

如果只有一方改动，可以只写对应部分：

```
1. 后端改动：
   - 具体描述...
```

### 3. 脚注
- 关联 Issues：`Closes #123`
- 破坏性变更：`BREAKING CHANGE: xxx`
- 版本更新：`Build: 203 -> 212`

## 五、正确示例

### 前后端都有改动
```
feat(全端): 添加对战经验奖励与账号实时更新功能

1. 后端：
   - 重构经验值计算逻辑，支持返回完整更新结果
   - 对战结束后根据胜负和难度发放对应经验奖励
   - 经验变更后主动推送账号更新到客户端
   - 优化五子棋AI开局行为，首步优先下在用户棋子附近
   - 调整AI搜索深度与候选位置数量，优化性能
   - 新增AI思考日志便于调试

2. 前端：
   - 新增账号等级和经验值显示样式
   - 适配服务端新的账号数据结构
   - 新增经验值更新日志打印

Build: 203 -> 212
```

### 只有后端改动
```
fix(后端-AI): 修复困难模式第一步响应过慢

1. 后端：
   - 第一步下在用户棋子附近，避免大范围搜索
   - 降低搜索深度从7-10层到4-6层
   - 减少候选位置从15个到10个
```

### 只有前端改动
```
style(前端-界面): 美化账号栏等级和经验显示

1. 前端：
   - 添加渐变背景和圆角样式
   - 优化文字阴影效果
   - 调整内边距和字体大小
```

## 六、错误示例

- ❌ `fix: 修复bug`
- ❌ `update code`
- ❌ `WIP: 新功能`
- ❌ `feat: 添加了很多功能`
- ❌ `fix: 修复前后端问题，没有区分`
